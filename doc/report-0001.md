## 3. Принятые допущения

- Основная версия формы — 2.0. XFA-версия 1.0 и draft01 отклоняются.
- Стек: Python 3.12, Django 5.2 LTS, PostgreSQL 17, gunicorn, nginx. Отдельного брокера очередей на MVP нет.
- `extract_static.py` и `acroform.py` копируются в приложение без изменений и вызываются как функции. Когда форма будет утверждена — переход на пакет Python из проекта форм.
- Работа — отдельная сущность «преподаватель + студент + задача». Одна анкета соответствует одной работе, ключ повторной загрузки — ID анкеты.
- Расписание — текстовое поле работы, а не отдельная сущность: в схеме 2.0 это свободный текст.
- Статус из анкеты хранится как есть; для отчётов добавлена категория статуса, которую выбирает пользователь.
- Анкеты с ошибками проверки можно исправить в предпросмотре и сохранить. Анкеты без ID может принять ответственный, система назначает временный ID.
- Система не проверяет извлечённый JSON по JSON Schema 2.0 (из-за примера 17).
- Объём: до 50 кафедр, 1 000 преподавателей, 10 000 студентов, 20 000 работ.
- Система может работать в закрытой сети: без CDN.

## 5. Расхождения в материалах формы

1. **`docs/static-form.md`, строка 135:** «Сообщения выводятся в stderr, JSON записывается в любом случае». Это верно только для ошибок проверки (код 2). При ошибке извлечения (код 1) JSON не выводится — так у примера 20 без ID и при отказе по версии схемы. Это видно из `extract_static.py` и описано в `examples/README.md` («При коде 2 JSON всё равно выводится в stdout, при коде 1 — нет»).
2. **Пример 17 и схема 2.0** (уже отмечено в `examples/README.md`, не решено): JSON с датой `7.10.2026` не проходит шаблон `date_filled`. В ТЗ это вынесено в вопрос 13; на систему не влияет.
3. **Значения из пробелов и пробелы по краям.** `check()` проверяет значения после `strip()`, а в JSON они остаются как введены (пример 18: фамилия и имя из пробелов). Строго говоря, это не ошибка, но получатель JSON должен обрезать пробелы сам. В ТЗ это учтено (раздел 5.3).
4. **`prompts/0008_improved.txt` и текущий набор примеров.** Промпт требует `examples/manifest.json` и ожидаемые `.json`, а в текущем наборе их нет: README говорит, что ожидания заданы в `CASES` генератора и в таблице README. Видимо, требование изменили позже, но в документации формы это изменение не отражено. На ТЗ не влияет.
5. **`acroform.py` импортирует `fontTools` на уровне модуля.** Поэтому для одного только извлечения нужна зависимость `fonttools`. Это не ошибка, но мешает переиспользованию; в ТЗ учтено (раздел 7.3).
